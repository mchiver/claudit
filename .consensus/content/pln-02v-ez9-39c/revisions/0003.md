# Claudit Design IV: Publishing

The repository at github.com/mchiver/claudit becomes the marketplace people install Claudit from, with one line typed in a Claude Code session. The repository is already public and the manifest validates; what is missing is a marketplace file, an install section in the Readme, and a server that runs from an installed copy.

## The install copy

An installed plugin is a copy of the repository as committed: no node_modules, and nothing installs them, so the server runs on Node alone. express is dropped from package.json and server/app.js is rewritten on node:http: a small router of its own for the API routes, the JSON body (up to 8 MB), the Server-Sent Events stream, and the static files under public/ (the content type by extension, index.html for the root). The routes, the responses and the archive are unchanged, and the server tests keep passing against the same addresses. server/launch.js and the mod do not change. package.json gains an `engines.node` field naming the version the server needs, and its dependencies are empty.

## The marketplace

`.claude-plugin/marketplace.json` beside plugin.json makes the repository a marketplace with one entry: name `mchiver`, owner `mchiver`, the plugin `claudit` with source `./`, since the repository root is the plugin. The marketplace is named mchiver, so an installed plugin is keyed claudit@mchiver and other plugins of mchiver's can be listed in it later; the install line is still `/plugin install claudit --marketplace mchiver/claudit`.

## The Readme

An install section goes in before the `--plugin-dir` section, which stays as the developer road:

- At the prompt of a terminal session: `/plugin install claudit --marketplace mchiver/claudit`
- From a shell: `claude plugin install claudit --marketplace mchiver/claudit`
- In the desktop app: the plus button next to the prompt, Plugins, Add marketplace with `mchiver/claudit`, then Add plugin.

It says that a developer loading the folder with `--plugin-dir` or `CLAUDE_CODE_PLUGIN_DIRS` should not also have the plugin installed, or the mod loads twice.

## What travels

The install copy holds everything committed: `.consensus/`, `.definitions/`, `.guides/`, CLAUDE.md and the tests. They stay; they are the project's record and the repository is public already. The engine's `.claude-plugin/types/` and the root tsconfig.json stay ignored.

## Checks

Before the release commit: the in-progress Design III work is committed and pushed first, so the release is its own commit. Then `npm test`, `claude plugin validate .` (which reads the marketplace file, the manifest and the hooks module together), and the plugin-authoring secrets scan over the folder, with every committed file read for anything that should not travel (a key, an internal path, someone else's data).

## The install test

In a fresh terminal session with `CLAUDE_CODE_PLUGIN_DIRS` unset, install from the folder as a marketplace (`claude plugin marketplace add <repo folder>`, then the install line), confirm the server starts from the installed copy, the page at http://127.0.0.1:3600 answers, `/claudit status` answers, and a turn's calls reach the archive. Then uninstall and remove the folder marketplace, so the dev folder and the installed copy never load together. After the push, the same once more from `mchiver/claudit`.

## The release

The version in plugin.json and package.json goes to 0.3.0. One commit titled "Claudit Design IV: Publishing", tagged `v0.3.0`, pushed with its tag. Later releases follow the same bump and tag; installers take them with `claude plugin update`.

## Later, not in this plan

A square PNG icon at `.claude-plugin/icon.png` and submission to the Anthropic plugin directory, which runs its own safety scan and policy review. The validator's warning that CLAUDE.md is not loaded as plugin context is left as it is: CLAUDE.md is for development, not for installers.
