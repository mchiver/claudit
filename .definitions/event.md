# Event

One record the mod posts to the server and the server streams and archives. Four kinds, all with `session` (the session id), `agent` (a subagent's id, null on the main loop) and times in milliseconds since the epoch:

- **A session mark**: `{ kind: "session", phase: "start" | "end", session, cwd, time, reason? }`.
- **A turn**: `{ kind: "turn", phase: "start", id, session, agent, text, time, cwd, truncated? }` when a user message starts it (`text` is that message, cut to the message limit), and `{ kind: "turn", phase: "end", id, session, agent, time, duration, reason, usage, cwd }` when it ends. `reason` is why: answer, aborted, refusal or error. The two share the `id` the engine gave the turn.
- **A call**: `{ kind: "call", id, session, agent, turn, tool, summary, start, end, duration, outcome, cwd }`. Posted twice: once when the call starts, with `outcome: "running"` and no end, and once when it finishes, with the same `id` (the `tool_use_id`) and the outcome `done`, `denied` (a hook refused it) or `failed` (the tool reported an error). The running one is live only; the finished one is archived. `summary` is one line: a shell call's description, a file tool's path, a search tool's pattern, else the tool's name.
- **A message**: `{ kind: "message", id, session, agent, turn, door, origin, time, message, cwd, truncated? }`. One row of the conversation as the engine keeps it: `message` holds its `type` (user, assistant, attachment, system), `role`, `name`, `isMeta` and `content` blocks (text, thinking, tool_use, tool_result, ...). `door` says how the row came in (prompt, response, tool-result, attachment, notice, ...). `id` is the row's uuid. Cut to the configured `message_limit`, with `truncated: true` when it was.

`turn` on a call or a message is the id of the turn it falls in: the mod stamps each with the loop's turn in flight, holds the rows that arrive before a turn starts until it does, and gives the rows appended after a turn ends that turn's id. `duration` is `end - start`.
